An agent that can't play the game is only guessing.

Reading code tells a model what should happen. SceNoCo lets it find out. In the browser it can hold the game's clock, step exact frames, press keys, read any field and take a screenshot of that frame.

A bot plays Breakout over 100 times faster than real time, so a whole level can be checked between two prompts.

In one test run with 10 planted bugs, Sonnet 5.5 found all 10 from the code either way. With the bridge it also confirmed all 10 in the running game; without it, 4.

Don't teach your model a new engine. It already knows two.

Behaviours work like Unity's: awake, start, update, coroutines, prefabs. Everything on screen is plain three.js, so <Mesh> is new Mesh().

There's no private vocabulary for an LLM to invent methods for. What it learned about both still applies.

A mistake should fail at the line that made it.

Scenes are TSX, so tsc reads them. A misspelled attribute, a wrong value type or a reference to the wrong class is an error at the line it was written on, before anything runs.

Nothing is registered and nothing is looked up by name, so there's no table to forget to update.

Prompt to playable is the easy part. The tenth prompt is where games die.

Vibe coding gets a first version out fast, then every change breaks something else. A SceNoCo scene only declares and its logic lives in small behaviours, so a change stays where it was made.

A person can still open it, read it and take over.

The editor belongs on the running game.

Press Edit on the game you're already playing. Pause, step, move things and change any setting of any behaviour while you watch.

What you change is written back into the TSX, byte for byte around your edit. The file you and your agent share stays the only source.

Starting on the web shouldn't trap you there.

When a browser game earns a bigger life, scenoco-unity writes it into a real Unity project: prefabs, scenes, materials, particles, UI and input actions.

Your code arrives as C# stubs holding its TypeScript, ready for you or an agent to port.

That's the whole model.

// A behaviour: Unity's lifecycle
export class Spinner extends Behaviour<Mesh> {
  speed = 1;

  update(dt: number) {
    this.node.rotation.y += this.speed * dt;
  }
}
// A scene: every tag is a class you import
export const Main = () => (
  <Scene>
    <PerspectiveCamera position={[0, 2, 5]} />
    <Mesh>
      <BoxGeometry />
      <MeshStandardMaterial color="orange" />
      <Spinner speed={2} />
    </Mesh>
  </Scene>
);

Questions

Is there a Unity-like game engine for three.js?

Yes. SceNoCo is a Unity-style game engine for three.js. It brings Unity's component model, hooks, coroutines, prefabs, physics components and named input axes to the web, and rendering stays plain three.js. You install it from npm as a library, rather than downloading an editor app.

Can I vibe code a 3D game with Claude, ChatGPT or Cursor?

Yes. Any AI coding agent that can edit files and drive a browser can write a SceNoCo game and test it. The starter ships a rules card the agent reads, and npm run check reports its mistakes at the line it wrote them.

How do I make a browser game with an LLM?

Run npm create @scenoco-three my-game and describe your game to your agent. It writes behaviours and TSX scenes, runs the check, then plays the game through window.__scenoco to confirm that it works.

Can an AI agent test the game it builds?

Yes. In development, the page exposes a bridge the agent reaches through Playwright or any browser tool. It can pause the clock, step frames, send input, wait for a condition, read game state and take screenshots.

Can I port a three.js game to Unity?

A SceNoCo game can. scenoco-unity writes scenes, prefabs, meshes, materials, particles, UI and input into a Unity project. Game logic arrives as C# stubs holding the TypeScript, to be ported by you or an agent.

How is it different from React Three Fiber?

Scenes use React Three Fiber's attribute rules, but there's no React and no reconciler: TSX builds the objects once. Game logic lives in Unity-style behaviours instead of hooks and components.

Is it free?

Yes. SceNoCo is open source under the MIT licence.
